## 2. 기준선 (Baseline) 정의

모든 검증은 다음 기준선과 비교한다.

## 3. 확률 보정 (Calibration)

### 3.1 왜 필요한가
모델 점수를 "확률"이라 부르려면 "p = 0.4라고 말한 경우들 중 실제로 약 40%가 그 결과가 되어야" 한다. 금융 수익 예측은 신호 대 잡음비가 매우 낮아 과신(overconfidence)이 흔하다.

### 3.2 방법
- Champion: Temperature scaling (1 파라미터).
- Challenger(GBDT): Isotonic (calibration fold ≥ 10,000 표본) 또는 Temperature.
- Calibration fold는 β 추정 데이터와 분리 (`QUANT_MODEL_SPEC.md §11.5`).

### 3.3 지표
| 지표 | 정의 |
|---|---|
| ECE_k | 클래스 k의 one-vs-rest: 예측확률로 정렬해 10개 동일표본 구간 b, ECE = Σ_b (n_b/n) \|mean(p) − mean(1[Y=k])\| |
| 신뢰도 기울기·절편 | logit(1[Y=k]) ~ a + b·logit(p_k) 로지스틱 회귀 (Cox calibration). 이상적 a=0, b=1. b<1 = 과신 |
| Brier 분해 | Murphy(1973) "A New Vector Partition of the Probability Score", J. Applied Meteorology 12(4):595–600, 10.1175/1520-0450(1973)012<0595:ANVPOT>2.0.CO;2 — Reliability, Resolution, Uncertainty |
| 다중클래스 | 클래스별 ECE의 최대값을 대표값으로 사용 (가장 나쁜 클래스 기준) |

### 3.4 통과 기준 [PARAM]
- max_k ECE_k ≤ 0.03
- 기울기 b ∈ [0.8, 1.2], 절편 \|a\| ≤ 0.1 (각 클래스)
- 신뢰도 곡선의 각 구간 관측빈도가 예측 평균의 부트스트랩 95% CI를 벗어나는 구간 ≤ 2개

### 3.5 하위 집단 보정
시장 국면(§10.4 5개 코드), 변동성 3분위, 신뢰도 등급별로 ECE 보고. 특정 하위 집단 ECE > 0.06이면 해당 집단에 신뢰도 캡(최대 C) 적용 여부 검토.

### 3.6 확률 표시 정책

| 상태 | 조건 | UI 표시 |
|---|---|---|
| `DISPLAY_FULL` | 최근 출시 검증 + 최근 252일 롤링 ECE ≤ 0.03 | 상승/횡보/하락 % 수치 표시 |
| `DISPLAY_COARSE` | 0.03 < 롤링 ECE ≤ 0.05 | 5%p 단위 반올림 + "보정 점검 중" 배지 |
| `DISPLAY_HIDDEN` | ECE > 0.05 또는 표본 부족 (만기 도래 신호 < 2,000) | 수치 숨김, "확률 보정 검증 중" 문구 + 방향 우위(강/중/약)만 |

## 4. 통계적 유의성

| 질문 | 검정 | 기준 |
|---|---|---|
| 모델 예측이 기준선보다 나은가 | Diebold-Mariano (손실: 로그손실, HAC lag = h, 날짜 단위 평균 손실 차이 시계열) | p < 0.05 |
| 여러 후보 중 최고 모델이 우연인가 | Hansen SPA (J2), 부트스트랩 1,000회 | p < 0.05 |
| 동등하게 좋은 모델 집합 | MCS 90% (J3) | Champion ∈ MCS |
| Sharpe가 시행 횟수 대비 유의한가 | DSR (J4) | ≥ 0.95 |
| 백테스트 과적합 확률 | PBO via CSCV (J5) | < 0.20 |
| 두 전략 Sharpe 차이 | Ledoit-Wolf (J8) | 보고 |
| Feature 선별 | Fama-MacBeth + Newey-West t, BH-FDR 10% (J11) | t > 3.0 (L2) |
| 횡단면 예측력 | 날짜별 Spearman IC의 평균, Newey-West t | 보고 |

### 4.1 효과 크기에 대한 기대 관리
McLean-Pontiff(L1)에 따라 문헌 효과는 발표 이후 감소한다. 내부 의사결정에서 사용하는 기대 성과는 walk-forward 결과가 아니라 **walk-forward의 최근 5년 구간 결과와 lockbox 결과 중 작은 값**으로 한다.

## 5. 운영 감시 (Monitoring)

### 5.1 신호 원장과 사후 평가

- 모든 신호는 산출 즉시 `signal_ledger`에 해시 체인으로 기록 (`SYSTEM_ARCHITECTURE.md §6.3`).
- 만기 도래(t+1+h 시가 확정) 후 `signal_outcomes`에 X, Y, 비용 차감 수익을 기록. 원장 레코드는 수정 불가, 결과는 별도 테이블로 연결.
- 데이터 정정(벤더 수정)으로 결과가 바뀌면 결과 레코드에 새 버전을 추가하고 이전 버전 보존.

### 5.2 감시 지표와 경보

| 범주 | 지표 | 주기 | 경보 기준 [PARAM] |
|---|---|---|---|
| 데이터 | 결측률, 이상 수익 건수, 벤더 지연 | 일 | 결측률 > 2% 또는 지연 > 2시간 → 신호 공개 중단(`H_DATA`) |
| Feature 드리프트 | PSI (학습 분포 vs 최근 21일), Feature별 | 일 | PSI > 0.25 → ALERT, 0.10–0.25 → WARN |
| 예측 분포 | E의 평균·분산, BUY/SELL 비율 | 일 | BUY 비율이 학습 분포 1–99% 분위 밖 → WARN |
| 성능 | 롤링 126일(만기 도래분) BSS, 로그손실 | 주 | BSS의 90% CI 상한 < 0 → ALERT |
| 보정 | 롤링 252일 ECE | 주 | §3.6 표시 정책 자동 전환 |
| 누적 감시 | 일별 (로그손실_model − 로그손실_BL0) 의 Page-Hinkley/CUSUM | 일 | 임계 초과 → ALERT |
| 경제 성과 | P_BUY_EW 롤링 1년 초과수익 | 월 | 백테스트 분포 하위 5% → 검토 |
| 등급 | 등급별 적중률 순서 (A > B > C > D) | 월 | 역전 2개월 연속 → 등급 재검토 |
| 국면 엔진 | π^HV 일변동 > 0.5 빈도 | 월 | 불안정 경보 |

PSI = Σ_b (a_b − e_b) ln(a_b/e_b), 10개 분위 구간(학습 분포 기준).

### 5.3 경보 대응

| 수준 | 자동 조치 | 사람 조치 |
|---|---|---|
| WARN | 대시보드 표시 | 주간 리뷰에서 원인 기록 |
| ALERT (성능/누적) | 해당 시장·기간 신뢰도 최대 C (`c_model = ALERT`) → 신규 BUY/SELL 발생 억제(HOLD_UNCERTAIN), 모델 성과 페이지에 공지 | 48시간 내 원인 분석, 재학습 또는 롤백 결정 |
| 데이터 FAIL | 해당 일 신호 미공개, 이전 신호 유지 + "업데이트 지연" 표시 | 데이터 복구 후 재실행 |

### 5.4 공개 성과 집계 규칙 (`UI_UX_SPEC.md` 모델 성과 화면)
- 기간 창: 최근 30일 / 90일 / 1년 / 전체 — **만기 도래일 기준**으로 신호를 포함 (아직 결과가 없는 신호는 제외하고 "진행 중 n건"으로 별도 표시).
- 최소 표본: 독립 날짜 수 ≥ 20 이고 신호 수 ≥ 100 미만이면 수치 대신 "표본 부족" 표시 [PARAM]. 30일 창의 Mid(63일) 성과는 정의상 만기 도래가 없으므로 Short만 표시.
- 모든 비율에 95% CI (날짜 클러스터 부트스트랩).
- 백테스트 성과와 실시간(원장) 성과를 **다른 섹션·다른 색상**으로 분리하고 "가상 성과(백테스트)" 라벨 상시 표시.
- 성과 계산식과 비용 가정을 페이지에 공개.

## 6. 재학습·변경 관리

### 6.1 버전 체계 `{MARKET}-{S|M}-{MAJOR}.{MINOR}.{PATCH}`

| 변경 유형 | 예 | 버전 | 필요한 검증 |
|---|---|---|---|
| PATCH | 정기 재추정(같은 명세, 데이터만 확장), 버그 없는 리팩터 | x.y.**z** | 자동 회귀 테스트 + 계수 변화 검사 (`COEF_SHIFT`) + 직전 버전 대비 최근 1년 OOS 로그손실 열화 없음 |
| MINOR | 하이퍼파라미터 격자·임계값 재선택, 보정 방법 변경 | x.**y**.0 | Walk-forward 전체 재실행 + C1–C7 |
| MAJOR | Feature 추가·제거, 모델 구조 변경, 라벨 정의 변경 | **x**.0.0 | §15(모델 명세) 절차 + C1–C10 전부 + Shadow 63일 |

### 6.2 정기 재학습
- 분기 1회 (1·4·7·10월 첫 거래일 이전 주말), 확장창 PATCH.
- 재학습 모델은 1개월 Champion과 병행 산출(그림자) 후 교체 — 단 PATCH는 계수 변화 기준 통과 시 즉시 교체 가능 [PARAM].

### 6.3 트리거 재학습
ALERT 발생 시: (1) 데이터 원인 배제 (2) 최근 데이터 포함 재추정 PATCH 후보 생성 (3) PATCH가 경보를 해소하지 못하면 해당 조합 신호 공개 중단 고려 + MAJOR 연구 착수. **최근 성과가 나쁘다는 이유만으로 Feature 가중을 임의 조정하지 않는다.**

### 6.4 Champion–Challenger
- Challenger는 항상 그림자로 산출·기록(비공개). 승격은 §6.1 MINOR/MAJOR 절차.
- 동시에 운영되는 Challenger 수 ≤ 3 (다중검정 관리).

### 6.5 롤백
모든 배포 모델 아티팩트(계수, 보정 T, 스케일러, Feature 정의 해시)는 불변 저장. 롤백 = 이전 버전 포인터 변경 + 원장에 `MODEL_ROLLBACK` 이벤트 기록.

### 6.6 변경 이력
`model_registry` 테이블:
```
model_version, market, horizon, spec_hash, artifact_uri, artifact_sha256,
train_window, data_snapshot_id, code_commit, validation_report_uri,
approved_by, approved_at, deployed_at, retired_at, change_type, change_reason
```
공개 모델 카드(§8)에 버전 이력과 변경 사유 요약을 게시.

## 9. 검증 책임과 독립성
- 모델 개발자와 검증자를 분리 (최소: 다른 사람이 V3, C8 확인).
- Lockbox 개봉 권한은 검증자에게만.
- 검증 리포트는 저장소 `reports/validation/`에 커밋, 해시를 모델 레지스트리에 기록.
