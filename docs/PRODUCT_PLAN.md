버전 0.1 (설계 단계) · 관련 문서: `QUANT_MODEL_SPEC.md`, `UI_UX_SPEC.md`, `DEVELOPMENT_ROADMAP.md`, `LEGAL_REGULATORY_REVIEW.md`

## 1. 서비스 철학

### 1.1 한 문장 정의

BUY OR SELL은 **"이 종목을 지금 사거나 팔 통계적 근거가 있는가, 그리고 그 근거를 얼마나 믿을 수 있는가"** 를 재현 가능한 수학 모델로 계산해 개인 투자자에게 BUY / HOLD / SELL로 전달하는 서비스다.

### 1.2 우리가 하는 것과 하지 않는 것

| 하는 것 | 하지 않는 것 |
|---|---|
| 학술적으로 검증된 가격·거래량 기반 효과(모멘텀, 단기 반전, 저변동성 등)를 조합해 **조건부 확률**을 산출 | 주가 목표치(target price) 제시 |
| 거래비용을 차감한 기대 초과수익과 하방 위험을 동시에 고려 | LLM이 BUY/SELL을 결정 |
| 확률이 **보정(calibrated)** 되었는지 지속 검증하고 공개 | 보정되지 않은 점수를 "확률"로 표시 |
| 과거 모든 신호를 변경 불가능한 원장에 기록하고 사후 성과를 공개 | 과거 신호를 사후 수정·삭제 |
| 근거가 부족하면 **HOLD(판단 보류)** 라고 명확히 말함 | 매일 모든 종목에 강한 신호를 남발 |
| 개인별 포트폴리오와 무관한 일반 정보 제공 (MVP) | 개인 맞춤 자문, 자동매매, 주문 대행 |

### 1.3 AI의 역할 경계

- **설계 시점(오프라인)**: 연구 탐색, 전략 후보 발굴, 재현성 평가, 백테스트 코드 작성 보조, 결과 해석 보조.
- **운영 시점(온라인)**: 신호는 버전 관리된 결정론적 파이프라인(`SYSTEM_ARCHITECTURE.md §5`)이 산출. LLM은 *이미 산출된* 수치를 자연어로 풀어 쓰는 "설명 렌더러"로만 쓸 수 있으며(Phase 2 이후, 선택 기능), 그 출력은 템플릿 기반 설명과 수치 일치 검사를 통과해야 노출된다. 신호·확률·신뢰도 값에 LLM 출력이 입력되지 않는다.

## 2. 핵심 가치와 제품 원칙

| 가치 | 제품 원칙 (측정 가능한 형태) |
|---|---|
| Quantitative Evidence | 모든 신호 요인은 `QUANT_RESEARCH.md`에서 Core/Supporting으로 분류된 연구에 매핑되어야 한다. 매핑 없는 요인은 운영 모델에 들어갈 수 없다. |
| Statistical Reliability | 운영 모델은 Deflated Sharpe Ratio, SPA 검정, 확률 보정 기준(`MODEL_VALIDATION_SPEC.md §3`)을 통과해야 배포된다. |
| Reproducibility | 신호 = f(데이터 스냅샷 해시, 모델 버전, 코드 커밋). 세 값이 같으면 결과가 비트 단위로 같아야 한다. |
| Transparency | 화면의 모든 숫자에 "정의 / 산출식 / 데이터 기준 시각" 툴팁 제공. 모델 카드 공개. |
| Accessibility | 첫 화면 3초 이해: 판단 1개 + 투자기간 + 신뢰도 등급 + 한 줄 근거. |

**최우선 원칙**: 지표·전략 수를 늘리는 것은 성과가 아니다. 새로운 요인은 기존 모델 대비 Out-of-Sample 개선이 통계적으로 확인될 때만 추가한다 (`MODEL_VALIDATION_SPEC.md §6 변경 승인 기준`).

## 4. 서비스 시나리오

### S1. 보유 종목 점검 (P1)
1. 앱 진입 → 검색창에 "삼성전자" 입력 → 자동완성 선택.
2. 첫 카드: `단기(2주) HOLD · 신뢰도 B` / `중기(3개월) BUY · 신뢰도 B`.
3. 한 줄 근거: "12개월 상대 모멘텀 상위권, 최근 변동성은 평균 수준."
4. 아래로 스크롤 → 상승/횡보/하락 확률 막대, 주요 위험 요인("시장 국면: 고변동성 진입 확률 상승").
5. 사용자는 보유를 유지하기로 결정. 서비스는 결정을 기록하지 않는다(MVP는 계정 없음).

### S2. 신호 근거 확인 (P2)
1. 종목 상세 → "판단 근거" 섹션 → 요인별 기여도 막대(모멘텀 +, 단기 반전 −, 변동성 0).
2. 각 요인 탭 → 정의, 계산식, 관련 논문 링크, 이 요인의 과거 OOS 예측력.
3. "과거 유사 신호" → 같은 신호 등급이 과거에 발생한 후 2주/3개월 초과수익 분포.

### S3. 모델 신뢰성 검증 (P3)
1. 상단 메뉴 "모델 성과" → 최근 30일/90일/1년/전체 성과, 보정 곡선, 국면별 성과 표.
2. "신호 원장" → 특정 날짜의 전 종목 신호와 해시 확인, 사후 결과 대조.

### S4. 시장 환경 확인 (공통)
1. 홈 상단 "시장 국면" 위젯 → 미국/한국 각각 `상승 추세 · 저변동성` 등과 국면 확률.
2. 국면이 "위기(고변동성 하락)"일 때 모든 BUY 신호에 경고 배지 표시.

### 5.2 신호 정의 (사용자 대상 문구)

| 신호 | 사용자 문구 | 내부 정의 (`QUANT_MODEL_SPEC.md §13`) |
|---|---|---|
| BUY | "해당 기간 동안 시장 대비 초과수익 가능성이 통계적으로 유의하게 높습니다." | 보정 확률 우위 + 비용 차감 기대 초과수익 > 0 + 신뢰도 하한 + 위험 게이트 통과 |
| SELL | "해당 기간 동안 시장 대비 부진할 가능성이 높거나 하방 위험이 큽니다. 보유 중이라면 비중 축소를, 미보유라면 신규 매수 회피를 고려할 근거입니다." | 하락 확률 우위 또는 위험 게이트 발동 |
| HOLD | "현재 매수·매도 어느 쪽도 통계적 우위가 충분하지 않습니다." + 사유 코드 | 우위 부족 / 불확실성 과다 / 데이터 부족 / 국면 불안정 |

SELL은 공매도 권유가 아니다. 모든 판단은 **시장(벤치마크) 대비 상대 성과** 기준이며, 절대 수익을 약속하지 않는다.

### 5.3 커버리지 (MVP)

| 시장 | 유니버스 | 대략 종목 수 |
|---|---|---|
| 미국 | S&P 500 + S&P MidCap 400 구성종목 중 유동성 필터 통과 종목 (point-in-time 구성 아님 → 운영은 현재 구성, 백테스트는 PIT 유니버스 규칙 `BACKTEST_SPEC.md §2`) | ~900 |
| 한국 | KOSPI 200 + KOSDAQ 150 구성종목 중 유동성 필터 통과 종목 | ~350 |

ETF, 우선주, SPAC, 관리종목, 거래정지 종목은 MVP에서 제외 (`QUANT_MODEL_SPEC.md §2.3`).

## 6. MVP 범위

### 6.1 포함

F1–F10, 미국·한국 두 시장, 단기(10거래일)·중기(63거래일) 두 기간, 일 1회 장 마감 후 갱신, 반응형 웹(모바일·데스크톱), 비로그인 열람.

### 6.2 제외 (명시적)

계정·결제·알림·관심종목, 일중 데이터, 재무제표 팩터(검증 전), LLM 설명, 포트폴리오 기능, 공개 API.

### 6.3 MVP 출시 전제 조건 (Hard Gate)

1. `BACKTEST_SPEC.md`의 잠금 홀드아웃(lockbox) 테스트에서 각 시장·기간 모델이 사전 등록 기준 통과 — 통과하지 못한 시장/기간 조합은 **출시하지 않거나 "실험(Beta)" 표시**.
2. 최소 3개월(63거래일) **전진 그림자 운영(shadow forward test)** — 신호를 원장에 기록만 하고 공개하지 않은 기간의 결과가 백테스트 분포의 하위 5% 밖에 있지 않을 것.
3. 법률 검토(`LEGAL_REGULATORY_REVIEW.md §5`) 완료.

### 6.4 MVP 성공 지표

| 구분 | 지표 | 목표 |
|---|---|---|
| 모델 | 출시 후 6개월 OOS Brier Skill Score (vs 기저율) | > 0 이고 95% 블록 부트스트랩 CI 하한 > 0 은 *관찰 목표*(사전 약속 아님) |
| 모델 | 보정 오차 ECE | ≤ 0.03 (`MODEL_VALIDATION_SPEC.md §3.4`) |
| 제품 | 검색→판단 카드 도달 시간 | p75 < 2초 |
| 제품 | 상세 근거 섹션 도달률 | 30% 이상 (핵심 가치 '투명성' 사용 여부) |
| 신뢰 | 방법론/모델 성과 페이지 방문율 | 10% 이상 |

## 7. 제품 차별점

| 일반적 서비스 | BUY OR SELL |
|---|---|
| "AI가 분석한 매수 추천" (블랙박스) | 학술 근거에 매핑된 요인 + 수학적 정의 공개 |
| 적중률 강조 (기저율·비용 무시) | 비용 차감 초과수익과 적중률을 분리, 기저율 대비 Skill Score 공개 |
| 점수를 "확률 87%"로 표기 | 보정 검증 통과 시에만 확률 표기, 보정 곡선 공개 |
| 과거 성과를 백테스트로만 제시 | 실시간 원장 기반 실제 신호 성과와 백테스트 성과를 분리 표시 |
| 항상 매수/매도 의견 | 근거 부족 시 사유를 밝힌 HOLD |
| 시장 국면 무시 | 국면 확률을 산출하고 국면별 모델 성과를 공개 |

## 8. 수익 모델 (검토 — MVP 이후)

| 옵션 | 장점 | 규제 영향 (`LEGAL_REGULATORY_REVIEW.md`) |
|---|---|---|
| 무료 + 광고 | 진입장벽 낮음 | 금융 광고와 신호의 이해상충 관리 필요 |
| 프리미엄 구독 (스크리너, 알림, 상세 검증 데이터) | 정합성 높음 | 한국: 대가를 받는 불특정 다수 대상 투자판단 정보 제공 → **유사투자자문업 신고 대상 가능성** |
| B2B 데이터/위젯 | 고단가 | 시장 데이터 재배포 라이선스 비용 증가 |

MVP는 무료·비로그인으로 시작해 규제·라이선스 리스크를 최소화하고, 유료화 전에 법률 검토를 완료한다.

## 9. 주요 제품 리스크

| 리스크 | 대응 |
|---|---|
| 모델이 OOS에서 유의한 예측력을 보이지 않음 | 출시 게이트로 차단. 해당 시장/기간은 "연구 중"으로 표기하고 출시하지 않음 — 이것도 정직한 결과로 수용 |
| 사용자가 신호를 확정적 예언으로 오해 | 확률·신뢰도·위험 고지의 상시 노출, "시장 대비" 문구, 첫 방문 온보딩 |
| 신호 변경이 잦아 신뢰 하락 | 히스테리시스와 최소 유지 기간 (`QUANT_MODEL_SPEC.md §13.4`) |
